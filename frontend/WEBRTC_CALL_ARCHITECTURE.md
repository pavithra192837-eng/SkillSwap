# SkillSwap 1-to-1 Calling Architecture

## Goal

Reliable two-person voice/video calls between phone and laptop without an embedded meeting provider.

## Architecture

```text
Messages / Sessions
        |
        v
Firebase RTDB invitation
        |
        +---- incomingCalls/{userId}/{callId}
        |
        v
Call screen on both devices
        |
        v
Firebase RTDB signaling
calls/{callId}/signals
        |
        | offer / answer / ICE candidates
        v
Native browser WebRTC
        |
        +---- direct ICE path (preferred)
        |
        +---- TURN relay (fallback)
        |
        v
Two-way audio/video
```

## Why this design

1. Firebase is only the rendezvous/signaling layer. It does not carry audio/video.
2. WebRTC carries the actual media directly when possible.
3. TURN relays media when NAT/firewalls prevent a direct path.
4. Perfect negotiation prevents offer collisions and avoids the caller/callee code paths fighting each other.
5. ICE restart is used after network interruption instead of destroying the call immediately.
6. Every asynchronous WebRTC operation is tied to a call generation. A stale callback cannot operate on a closed `RTCPeerConnection`.
7. ICE candidates are queued until a remote description exists.
8. Mute/camera toggles change track state and do not unnecessarily renegotiate.
9. Ending a call closes the peer, stops local tracks, removes the invitation, and marks the call ended.

## Production TURN requirement

Set these frontend variables to a TURN service you control or provision for your application:

```env
VITE_TURN_URL=turn:your-turn-server.example.com:3478
VITE_TURN_USERNAME=short-lived-username
VITE_TURN_CREDENTIAL=short-lived-credential
```

For production, prefer short-lived TURN credentials generated by your backend rather than a permanent credential shipped in the frontend bundle.

## Failure handling

| Failure | Recovery |
|---|---|
| Caller leaves before answer | Receiver sees `ENDED` and closes |
| Receiver leaves | Caller sees `ENDED` and closes |
| Temporary network loss | `disconnected` -> ICE restart |
| ICE failure | `restartIce()` -> renegotiation |
| Offer collision | Perfect negotiation / polite peer rollback |
| Candidate arrives early | Queue until remote description |
| Old async callback | Call-generation guard ignores it |
| Microphone/camera denied | Clear permission error |
| Firebase reconnects | Call media is not forcibly ended by Firebase disconnect |
| Stale ringing invitation | Manager expires old invitation |

## Two-person vs group calls

For two people, this native WebRTC + TURN architecture is appropriate.

If SkillSwap later needs 3+ participants, recording, server-side moderation, or large rooms, add an SFU/media server. Do not replace this signaling design with a public meeting iframe just to solve 1-to-1 connectivity.
